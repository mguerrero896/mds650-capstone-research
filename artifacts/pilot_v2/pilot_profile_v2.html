MDS650 Pilot Data Feasibility Report

13–17 July 2026 · Pilot V2 correction · no full backfill or modeling

Executive summary

The five-day pilot can calculate the RV30 target and preserve every valid forecast origin. The first pilot was not acceptable because any option trade was labelled an event. Pilot V2 instead reports continuous activity and treats unusualness as a future, trailing calibration problem. Existing raw ZIPs and filtered Parquet were reused without re-download.

Question answered

Does point-in-time option activity add information beyond underlying and market controls for the next 30 one-minute returns? This pilot checks data feasibility and timing only; it does not estimate predictive performance.

Coverage and quality

  • All 2,840 valid origins retained; 2,840 contain eligible option activity and 0 are fabricated no-operation origins.
  • B2 primary cutoff is created_at ≤ origin − 60 seconds; created_at is labelled an operational availability proxy, never publication time.
  • 506 of 515 IV inversions succeeded; nine failures are preserved individually. The existing exploratory matrix covers 72 origins and is not yet primary-study usable.
  • FMP exact-session probes returned 390 regular-session rows for each tested common-history date; symbol-specific earnings timing returned HTTP 200. SPY/QQQ are not applicable; TSLA has no event in the pilot window.
  • Corrected common-history v2 passes six sampled dates (Jan/Jul 2024, Jan/Jul 2025, Jan/Jul 2026) across FMP, UW file availability, and Massive historical contract/quote probes.

Why V1 showed 100% event origins

V1 used “at least one option trade” as the event definition. In liquid assets that condition is nearly always true, so 2,840 origins were labelled events and none were labelled no-event. This is a classification error, not evidence that all activity was unusual.

Blockers and next steps

Remaining: Massive quote extraction must be run per origin across the full candidate matrix; B1 PIT and coverage acceptance are pending. Trailing unusualness cannot be calibrated from five sessions. Backfill, asset freeze, modeling, QLIKE and final evaluation remain blocked.

After Pilot V2 passes its gates, request (rather than automatically execute) a 20-session extension for trailing calibration.
